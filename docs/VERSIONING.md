# Политика версионирования MeshkitKeen

Версия форка хранится в `FORK_VERSION` (в `meshkitkeen.sh`), формат `MAJOR.MINOR.PATCH`.

| Цифра | Когда меняется | Пример |
|---|---|---|
| **MAJOR** (1-я) | Очень большое обновление — только по решению автора | `1.x.x` → `2.0.0` |
| **MINOR** (2-я) | Вышла новая версия **KeenKit** (синхронизация с апстримом) | `1.0.x` → `1.1.0` |
| **PATCH** (3-я) | Правки в собственном коде (баги, мелочи) | `1.0.0` → `1.0.1` |

Помимо этого автор вправе задать любой номер — окончательно версию определяет автор.

Версия апстрима KeenKit хранится отдельно — в `SCRIPT_VERSION` (сейчас `2.9.5`).

## Как выпустить релиз

1. Поменять `FORK_VERSION` (и `SCRIPT_VERSION`, если менялся KeenKit).
2. Закоммитить локально и запушить файлы в `main`.
3. Создать тег и релиз:

```sh
gh release create v<X.Y.Z> -R Chistovik92/MeshkitKeen \
  --target main \
  --title "MeshkitKeen v<X.Y.Z>" \
  --notes-file <путь к release notes>
```

Панель сама показывает «Доступно vX.Y.Z», когда на GitHub появляется релиз с
версией новее текущей (`check_update` сравнивает с `v$FORK_VERSION`).
